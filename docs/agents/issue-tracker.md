# Issue tracker: GitHub

Tracker: GitHub Issues, repositório `renancesarr/seo-agent-opencode`.
Usar `gh` pela conta própria do agente, seguindo as identidades de
[AGENTS.md](../../AGENTS.md). Specs e tickets aprovados recebem `ready-for-agent`.
Consultar issues e comentários antes de publicar para evitar duplicação.
Publicar corpos por arquivo com `--body-file`, com assinatura do agente.

Cada ticket aponta a especificação e suas dependências. Registrar bloqueios
com dependências nativas do GitHub quando disponíveis; caso contrário, usar
`Blocked by` no corpo com os números reais. Trabalhar apenas na fronteira
liberada pelas dependências. Não fechar a especificação pai ao gerar tickets.

PRs como superfície de triagem: não. Reviews seguem o fluxo obrigatório de PRs
entre agentes e promoção humana, sem mudança nos ADRs.
